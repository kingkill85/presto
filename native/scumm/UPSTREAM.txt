FRANK Quest derives its adventure engines from Cabal / ScummVM.
The decoder probe builds src/engines/scumm/bomp.cpp without modifying it.
That file is GPL-2.0-or-later; see the upstream COPYING and COPYRIGHT files.
The dependency audit builds a larger selection from the same revision without
source edits. Keep upstream per-file licenses when distributing any binaries.
No upstream source files or generated binaries are vendored in this directory.
The C/C++ probe wrappers in this directory are GPL-2.0-or-later.

Runtime/SD probe additions:
- Builds original common/stream.cpp, str.cpp and memorypool.cpp.
- Builds drivers/dlmalloc.c in fixed-arena, mspace-only mode (no OS allocation,
  mmap, morecore, threads or clock dependency). The build copy changes only
  `static struct malloc_params mparams` to an externally linked declaration
  so MicroPython can relocate its BSS through the GOT. Upstream dlmalloc has
  its own license header (public-domain/CC0); it remains in the build copy.
- Builds backends/fs/rp2350/rp2350-fs.cpp with one position fix: after a large
  read bypasses the 4096-byte buffer, refresh _bufStart from file_tell().
  Without this, pos() and subsequent SEEK_CUR operations use a stale offset.
  prepare_fs.py checks the exact expected source before applying that fix.
- Initialized data are mapped to the v1.26 loader's writable RAM image by
  prepare_data.py. Original object constructor sections are checked before
  stripping. Unsupported static initializers cause a hard build error.
- The read-only Cabal file API is supplied by file_bridge.c and MicroPython's
  scumm_files.ReadSession. No upstream Pico SDK/SD drivers are used.

Full-engine port additions:
- build_engine.py compiles 187 C++ translation units (SCUMM v5, supporting
  libraries and the RP2350 OSystem), plus our C platform/dynruntime bridge.
  It requires the exact clean revision above; generated transformations are
  outside that checkout and preserve all source license headers.
- The OSystem build copy removes Pico SDK IRQ/DMA includes and IRQ masking.
  No audio IRQs are installed; the engine runs on a single core. Presto's
  display DMA is left to the existing firmware. The default save path changes
  from /quest/saves to /sd/scumm/saves; noisy cursor logging is removed.
- engine_platform.c replaces the upstream PS/2/HDMI/audio platform. It presents
  RGB565 through MicroPython's Presto framebuffer, with exact 1x or optional
  1.5x nearest-neighbour output and matching cursor scaling.
- engine_bridge.c and scumm_backend.py provide timers, touch/gamepad events,
  file/directory access and write access restricted to the saves directory.
  Memory allocation remains confined to the caller-owned fixed arena.
- prepare_data.py --ram-bss places zero-initialized engine statics in the
  same writable native RAM image as initialized C++ data. This resolves local
  PC-relative BSS references; verified zero-filled image and on-device engine
  operation with the existing MicroPython 1.26 loader. Not flash-loader safe.
- Engine globals and singleton pointers are used for one session only. A
  second run requires reset; scumm.py resets to the desk on quit or failure.
- The link includes ARM GCC's libgcc and newlib libc/libm. Retain their
  respective licenses (including GCC Runtime Library Exception) when
  distributing generated binaries. malloc/free and reentrant variants are
  redirected into the fixed arena; OS/system allocation is unavailable.
- Audio and the generic ScummVM GUI/save menu remain disabled. The initial
  target is the official PLAYFATE DOS demo, not arbitrary game detection.

German Monkey Island VGA profile:
- Uses the existing ScummEngine_v4, GID_MONKEY_VGA, kGenRoomNum, %03d.LFL,
  German language and the upstream VGA MIDI flags. No engine source patches.

  VGA entry (8357 bytes). Only the user's local LFL/LEC files are deployed.

Shared menu update: exports state(op,slot), querying save/load availability and
requesting engine-native slots 1-5. Requests are applied by the normal SCUMM loop
after the Python menu returns. Generic ScummVM GUI remains disabled. Save-file
writes now stage and replace atomically through the Python filesystem bridge.
